## 宿題

- 取り組んだレベル：実装
- やったこと：
  - `app/ask.py` に `--chat` を追加し，会話履歴を保ったまま続けて質問できるようにした（`Conversation` クラス）
  - API はステートレスなので，user / model の発言を `types.Content` のリストとして自分で持ち，毎回 `generate_content` に履歴ごと渡す方式にした（`client.chats` に任せず，何を送っているかが見えるようにするため）
  - 履歴は往復ごとに入力トークンを増やすので，`MAX_TURNS = 10` 往復を超えた古い発言から捨てる
  - API エラーで失敗した質問は履歴に積まない（次の回答が崩れないように）
  - `/reset` で履歴の消去，`/exit` か空行で終了．各回答のあとにトークン数と履歴の往復数を表示する
  - `tests/test_ask.py` を追加．`generate_content` に渡された `contents` を記録する偽のクライアントで，API キーなしで次の4点を確かめた：2回目の呼び出しに1回目の質問と回答が含まれる／上限を超えると古い往復が捨てられる／`/reset` 後は履歴が空から始まる／`usage_metadata` が無くても落ちない
- 結果：`uv run pytest -q` で追加の4件を含めて通過
- 気づき・疑問：
  - 「覚えている」ように見えるのはアプリ側が毎回すべて送り直しているからで，長く話すほど入力トークン（＝料金とレート制限の消費）が増える．上限を何往復にするか，古い発言を捨てる代わりに要約して残すかは，用途ごとに決める設計項目だと分かった
  - 履歴を捨てると，最初に伝えた前提（名前や条件）も消える．大事な前提は system instruction に分けて，履歴の上限とは別に毎回送るのがよさそう（第3回のエージェントで試したい）
